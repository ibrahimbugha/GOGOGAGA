ERP Core Re-Implementation Rebuilding the transactional backbone of the business on Microsoft Dynamics 365 Finance & Operations

D365FO SCMFinanceAsset Management Production ControlProduct Information Mgmt
Summary

A fully-paid-for ERP system sat unused for lack of a workable data model. Rebuilt the core model, brought all 13 modules live, avoided a second implementation cost entirely.

Context

A Dynamics 365 F&O environment had been purchased but never adopted. Every department continued operating on manual general-ledger entries and paper production records, months behind the state of the actual business. Root-cause diagnosis traced the blockage to a single structural decision in the original setup: the system's Catch Weight (CW) feature, which made master planning impractical to implement and complicated the costing model beyond usable.

Approach
  1. Removed the Catch Weight feature and engineered a custom batch-attribute weight model — total batch weight derived from single-item weight × piece count, matching how extrusion production actually works.
  2. Redesigned product costing to a job-order model, aligning cost flow with the physical movement of item batches across production levels.
  3. Rationalized the item master — consolidated item variants that had been defined as standalone items into proper product variants, simplifying item coding and reporting.
  4. Implemented maintenance and full die lifecycle tracking across three modules: Fixed Assets (die as capitalized asset), Production Control (die as production resource), and Asset Management (maintenance history).
  5. Re-enabled master planning, unworkable under the old model, once the batch-attribute redesign made it implementable.
System Flow
Manual Ledger & Paper Records → Catch Weight (blocks planning & costing) → Batch-Attribute Model → Costing + Planning + Asset Tracking

Shop-Floor Integration & Real-Time Visibility Connecting production data to the system automatically, and making it visible

MES IntegrationSQL / SSAS Power BID365FO Production Control
Summary

Production data took 2+ days to reach management on paper. Built an automated data pipeline and dashboard suite that cut that to roughly 2 hours, with cross-departmental reporting that didn't exist before.

Context

Production data was recorded on paper and transcribed into Excel by hand. Aggregate figures reached management with a lag of 2+ days, true aggregates were only available weekly or at month-end, and cross-departmental performance indicators were practically impossible to produce or validate manually.

Approach
  1. Designed the MES-to-D365FO integration pattern for automated transaction posting, with integrity controls built into the flow that remove the user's ability to modify or corrupt open transactions.
  2. Architected a custom Entity Store model — the "Production Cube" — on the SQL/SSAS aggregate measurement architecture, consolidating inventory transactions, route/process-time transactions, and reference data including product classification and customer attributes.
  3. Built a 6-report Power BI suite, embedded directly as workspace pages inside D365FO: daily and monthly quantities, per-process cycle times, productivity, and scrap ratio by section, plus department-wide totals.
  4. Extended coverage to die manufacturing — dies produced daily, monthly, and per customer.
  5. Automated custom-product setup, previously a manual process spanning multiple forms for every new made-to-order product.
Data Flow
Shop Floor / MES → Integration Layer (integrity controls) → D365FO → Production Cube (SSAS) → Power BI Dashboards

Shop-Floor Integration & Real-Time Visibility From paper records to hourly-refreshed, cross-departmental reporting

Summary

Four manual bottlenecks closed at once — reporting lag, order entry time, product setup time, and the absence of any cross-department data to trust.

Results
2+ days → ~2 hrsmanagement data latency
20-30 → 3-5 minorder entry time
30-60 → 2-5 mincustom product setup

What changed

Cross-functional reporting that was previously impossible on paper became routine: stage-by-stage productivity comparison across production stages, an inter-departmental synchronization view, and validated scrap and productivity indicators across all departments — with data validation for the first time.

Technical notes

The integration layer's integrity controls were deliberate: the MES posts transactions automatically and the design removes any path for a user to modify an open transaction, closing a class of data-quality risk before it could occur rather than reconciling it after the fact.

Business impact

Leadership sees the floor as it happens. A decision that used to wait for a week-end report — a bottleneck, a scrap spike, a customer's order status — is now visible the same shift it occurs.

Intelligent Operations — AI & Extended Systems Applying AI agents to operational review, and extending system scope beyond the factory floor

Azure SecurityAI Agent Design D365FO Landed CostTransportation Mgmt
Summary

Built a reusable AI-agent pipeline for security review from scratch, and extended the ERP's scope to cover inbound and outbound logistics costing — both delivered in-house, no outside vendor.

Context

Two parallel initiatives extending the system's reach: the company's Azure subscription had no structured, repeatable process for security review; and inbound import costs together with outbound transportation had remained outside system scope, carried as pending work beyond the January 2026 go-live.

Approach — AI-Assisted Security Review
  1. Scripted automated extraction of targeted security configuration reports from the Azure subscription.
  2. Built a purpose-designed AI agent, using Claude, to analyze the extracted reports against a structured review standard.
  3. Ran the pipeline end-to-end to produce a repeatable security assessment — a process that did not exist before, now available on demand rather than as a one-off manual exercise.
Approach — Extended Logistics Scope
  1. Configured the Landed Cost module for inbound shipment costing.
  2. Configured Transportation Management (TMS) for outbound shipment logistics.
  3. Leading end-user training on both modules ahead of go-live.
AI Review Pipeline
Azure Config Data → Extraction Scripts → Claude Agent (Analysis) → Structured Security Report
